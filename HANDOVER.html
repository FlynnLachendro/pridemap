What PRIDE Map is

The problem. PRIDE (EMBL‑EBI's proteomics archive) holds 41,548 mass‑spectrometry datasets. Whether one can answer a researcher's question depends on how it was run: was the sample enriched for phosphopeptides? DDA or DIA acquisition? label‑free, TMT or SILAC? which enzyme, fractionation, instrument? None of those are structured fields in PRIDE. They live in free‑text protocol paragraphs and in the paper's Methods section. Charlotte's real experience: 800 hits, 20 papers opened by hand, three usable, and still no idea which search settings to use.

The solution. An LLM read every dataset's protocol text plus the paper's open‑access Methods (from Europe PMC) and emitted 14 closed‑vocabulary tags, each with a confidence, a source (metadata / paper / inferred) and the verbatim sentence it came from. On top of those tags: a PRIDE‑style browse with method filters and plain‑English questions, a treemap of the archive, comparability verdicts between datasets, a database‑search set‑up sheet per dataset (what to type into MaxQuant / DIA‑NN, with the quote behind each line), a quantms cloud kit, a downstream analysis step (fold change, Welch t‑test, FDR, volcano, publication bundle), collections, saved searches with alerts, OmicsDI cross‑omics links, an evaluation page, and an MCP server so an AI assistant can do all of it.

The loop the UI is built around (now shown as a rail at the top of every page): Find → Confirm → Set up → Analyse → Check. A human ticks each step; the machine writes the case, the parameters and the stats.

Built from zero during the hackathon: first commit Friday night, ~60 commits by handover. Stack: Python scripts with inline deps (uv run), one SQLite file, FastAPI, Next.js 16 + Tailwind 4 + shadcn, driver.js for the tour, Playwright for the recording, the MCP Python SDK.

Run it in 15 minutes

  1. Install uv and Node 20+. No venvs, no pip, no Postgres.
  2. git clone https://github.com/FlynnLachendro/pridemap && cd pridemap
  3. Create .env in the repo root from what Flynn sends you (4 lines, KEY=value). Without it the app still runs: /ask falls back to a rule‑based parser; only the live agent console on /mcp and the tagger need keys.
  4. ./dev.sh — first run loads the data bundle (data/demo/*.jsonl.gz, 113 MB, ~5 s) into data/pride.db, installs web deps, then starts the API on :8000 and the web app on :3000. Ctrl‑C stops both.
  5. Open localhost:3000. You should see the teal search band and facet counts. localhost:8000/docs lists the API.
  6. Click ▶ Take the tour in the sidebar. It runs itself for about 2.5 minutes across 10 pages and ends on /tour/done. If it does, you are ready.

Ports and processes

API 8000 (uv run api/main.py), web 3000 (npm run dev in web/), MCP over HTTP 8010 (uv run api/mcp_server.py --http, optional). dev.sh kills stale processes on 8000/3000 first.

First load is slower

A warmer thread fills the browse cache at API start (~2 s). After that the landing page answers in ~10 ms and filtered browses in 10–400 ms.

Data pipeline

  1. Crawl. All PRIDE project metadata, ~250 MB JSON, ~60 min.
  2. Build. One SQLite file in WAL mode: projects, papers, tags (one column per tag), tag_evidence (one row per tag per dataset: value, confidence, source, quote), corrections, projects_fts (FTS5, porter), plus collections and saved_searches.
  3. Methods. Europe PMC open‑access full text, Methods section extracted.
  4. Tag. The model sees the PRIDE fields, the protocols and the Methods text, and must answer with the 14‑tag schema. Closed vocabularies; every value carries its evidence sentence. First 1,661 by Claude Sonnet 5 (~$33), the rest by DeepSeek V4.1 Flash (~$1.5 per 1,000; 93% agreement with Sonnet on the benchmark).
  5. Serve. FastAPI reads the DB; the web app reads the API; the MCP server wraps the same tools.

Things that bit us (so they don't bite you)

  1. Anthropic structured outputs reject nested or optional‑heavy schemas ("Schema is too complex"). Every messages.parse(output_format=…) model is flat with all fields required.
  2. SQLite "database is locked" when the tagger, the paper fetcher and the API overlap: WAL mode plus timeout=120 on every connection. Keep it on new connections.
  3. FastAPI handlers must not take **kwargs (422s).
  4. Next.js 16: cacheComponents is incompatible with force-dynamic pages (it is off). The set-state-in-effect lint rule: use setTimeout(…, 0) in effects or derive state. Client caches read after mount or you get hydration mismatches.
  5. CSS watcher sometimes misses a save of globals.css: touch web/app/globals.css.
  6. Caches: browse 120 s, facets 60 s. New data shows after an API restart or within two minutes.
  7. HF router: model id deepseek-ai/DeepSeek-V4.1-Flash:deepinfra; thinking must be off or it reasons for ages; 402/429 on one token rotates to the next.
  8. Anthropic key: the one in .env is from Flynn's "Default" org (the other org has no credit). tag.py's loader overrides a stale shell variable on purpose.
  9. Collections list endpoint returns accessions now; the UI relies on it for membership ticks.

Likely judge questions

  • How accurate are the tags? The benchmark (93% agreement between the cheap model and Sonnet), every tag carries its sentence and confidence, "wrong?" feeds corrections back; the gold set gives a human number once filled.
  • Does it hallucinate? Every tag has a verbatim quote and a source (metadata / paper / inferred). Inferred tags are flagged and lower confidence. The UI never hides the evidence.
  • Can it run the reanalysis? No. MaxQuant and Mascot are desktop tools without APIs. It produces the set‑up sheet and a quantms/Nextflow kit so the search is one command in the cloud.
  • Why not PRIDE's own search? Keyword matching over prose; none of these properties are fields. PRIDE Map adds the fields.
  • Cost for the whole archive? About $60 with DeepSeek; about $1,000 with Sonnet. A nightly job keeps it current.
  • Datasets that actually contain protein X? PRIDE retired its protein‑evidence API. We search UniProt synonyms over text and label it "mentions"; peptide‑level evidence is on the roadmap.
  • Licensing? MIT code. PRIDE metadata under EBI terms; only open‑access Methods text is stored.
